# Human Design V0.4 Product Requirements

更新时间：2026-06-06

## Summary

V0.4 是 V0.3 地图式解读产品之后的体验深化版本，核心目标是把“能看懂”升级为“能被用户拿来理解自己”。本版本重点解决三类问题：

- 解读深度：每个天赋、通道、闸门、财富和关系条目不能只做单点解释，必须结合用户完整盘面做综合解读，讲清楚“这个特质真正活出来的人是什么样子”。
- 追问交互：每个推荐追问必须可点击，并把问题、地图条目、图表事实和资料库上下文带入聊天，进入大模型深度分析，而不是重复当前卡片文案。
- 阅读体验：BodyGraph 下半部分“人类图解读本”当前排版拥挤、文字不可读，V0.4 需要拆分图表与解读本布局，保证移动端和桌面端都能清楚阅读。

本版本仍保持产品边界：人类图用于自我观察、身体资源、能量管理、关系和事业理解，不做医疗诊断、心理诊断、投资建议或确定性命运预测。

## Product Positioning

V0.4 的产品关键词是“全盘综合解读”。用户不仅仅是来查“2/4 是什么”“02-14 是什么”；除了想知道这个特质本身的解读外，更想知道这个特质和全局中其他特质结合之后，如何形成自己的身体节奏、天赋表达、财富方式、关系模式和人生路径。

用户具体想知道：

- 我这个人整体是怎么运作的？
- 我的天赋在现实中怎么表现？
- 我怎么赚钱、怎么合作、怎么表达、怎么处理关系？
- 我为什么在生活中反复遇到某类事情？
- 这个盘活得成熟时是什么状态，卡住时又是什么状态？

因此，V0.4 所有解读必须从“术语解释”转成“图表事实叠加后的用户语言”。

## Core User Problems

### 1. 单点解读不够像本人

当前 V0.3 已经能输出地图条目，但部分内容仍偏向“某个中心/通道/爻位本身是什么”。用户真正需要的是：这个特质放在当前人的完整盘面中，如何形成一种具体的人格、身体节奏、赚钱方式、关系模式和人生路径。

### 2. 推荐追问不可直接使用

当前推荐追问更像文本提示。V0.4 要把它变成真实交互入口：用户点击问题后，系统自动进入聊天区，把问题发给模型，并带上当前条目的上下文和全盘综合上下文。

### 3. BodyGraph 解读本排版不可读

当前图表下半部分“人类图解读本”文字挤在固定画布里，阅读体验差。V0.4 要把正式 BodyGraph 与长解读排版拆开：图表负责核验盘面，解读本负责清晰阅读。

### 4. 示例与个人信息泄露风险

当前产品不允许把真实用户资料硬编码成“使用示例”。V0.4 必须移除默认示例按钮，不能在前端、公开文档、截图、导出报告或开源仓库中暴露真实用户姓名、生日、出生时间、出生地等个人信息。测试和验收可以使用匿名样本或合成样本。

## Priority

V0.4 的优先级排序：

- P0：隐私与输入重构。先移除真实资料示例、增加性别、隐藏国家和时区，再继续做深度内容。
- P0：全盘综合解读。所有核心条目必须从单点解释升级为“单点特质 + 全局组合”的解读。
- P0：特质诊断层。核心解读必须讲清这个特质真正活出来的人是什么样、盲区是什么、被卡住是什么状态，以及为什么会卡住。
- P1：点击追问深聊。推荐问题必须变成真实对话入口。
- P1：解读本排版重构。解决 BodyGraph 下方文字拥挤不可读的问题。

判断依据：如果产品一开始泄露真实个人信息，用户不会继续信任后面的深度解读；如果解读仍停留在单点术语，产品就没有形成真正差异化。

## Key Product Changes

### 0. 输入表单与隐私调整

- 删除“使用示例”按钮，不再用真实用户资料预填表单。
- 表单增加“性别”：男 / 女。
- 表单删除“国家”和“时区”两个用户可见字段。
- 中文主产品默认按中国标准时间处理；后端可保留 `timezone_name` 作为内部兼容字段，但不能让普通用户在首页填写或看到。
- 产品文档、验收样本、截图和测试描述必须使用匿名样本，不写真实用户姓名和完整出生资料。
- 任何公开 demo、默认 fixture、截图、README、SEO 页面、导出样例都不得使用真实用户的姓名、生日、出生时间和出生地。
- 若需要演示，可使用匿名合成样本，例如“测试用户 A”，且出生资料不得对应真实用户身份。

### 1. 综合盘面解读引擎

新增 `SynthesisContext`，每个地图条目生成时必须注入以下全盘事实：

- 基础身份：类型、策略、权威、人生角色、定义、签名、非自己主题。
- 身体结构：已定义中心、开放中心、主通道、关键闸门、人格面/设计面激活。
- 行动力结构：荐骨/情绪/脾/意志/自我等权威与中心状态。
- 关系结构：人生角色、开放中心、喉咙/情绪/意志/脾中心状态。
- 财富结构：荐骨、G中心、意志力中心、相关通道、14号闸门、2号闸门、通道回路。
- 使命结构：人格太阳/地球、设计太阳/地球、轮回交叉、关键闸门组合。

每个地图条目除了原来的“专业依据、用户语言、生活场景、卡点、练习”外，新增：

- `全盘综合`：解释这个特质与用户其他盘面配置如何叠加。
- `活出来的样子`：成熟表达时，这个人在生活、工作、关系中的具体状态。
- `盲区`：用户自己不容易意识到、但会反复影响现实选择的模式。
- `卡住状态`：现实中会表现成拖延、过度承诺、关系消耗、方向散、身体没劲、表达失真等哪一种。
- `卡住原因`：必须用“盘面机制 + 现实场景”解释原因，不只说“你要觉察”。
- `身体信号`：身体上如何识别对/不对，例如扩张、收缩、疲惫、卡住、兴奋、持续力。
- `现实落点`：放到财富、职业、关系、表达、学习或人生选择里怎么用。

### 2. 地图条目升级为“分层综合解读卡”

V0.4 地图条目不再只是知识卡，而是带有“特质诊断层”的分层综合解读卡。它不是所有条目机械加长，而是按条目重要性分层：

- `deep`：核心条目完整输出“活出来、盲区、卡住状态、卡住原因”四段诊断。
- `standard`：普通条目至少输出简版盲区和卡住状态。
- `trace`：专业信息条目只做事实核验和防误读，不展开成长篇诊断。

每个条目必须包含：

- 标题：用户语言标题，不只写术语。
- 专业依据：列出本条使用的图表事实，例如 `2/4`、`02-14`、`荐骨权威`、`开放意志力中心`。
- 一句话结论：直接告诉用户这条天赋/模式在他身上意味着什么。
- 全盘综合解读：`deep` 条目至少 300-600 字，必须把当前条目与完整盘面组合起来讲；`standard` 和 `trace` 条目不强制长篇。
- 活出来的人：至少 3 个具体画面，讲这个人成熟时会怎样工作、赚钱、合作、表达。
- 盲区：直接指出用户不容易自知、但会反复影响现实选择的模式。
- 卡住状态：具体写出卡住时的行为、身体状态、关系状态或财富状态。
- 卡住原因：必须同时包含盘面机制和现实场景。
- 可执行练习：至少 2 个现实练习，不能只是“多觉察”。
- 可点击追问：3-5 个问题按钮。

### 3. 可点击追问进入深度对话

所有推荐追问从纯文本升级为 `FollowupQuestionButton`。

点击后必须发生以下动作：

1. 自动把问题填入聊天输入区。
2. 自动发送到 `/api/chat`。
3. 请求中携带 `chart_id`、`map_type`、`map_item_key`、`question_id`、`synthesis_context`。
4. 聊天窗口滚动到最新回答。
5. 回答必须由 DeepSeek 或本地 fallback 基于当前问题重新生成，不能直接复用当前卡片内容。

大模型回答要求：

- 必须引用当前用户完整图表事实。
- 必须引用当前地图条目。
- 必须结合至少 2 个其他盘面特质进行综合分析。
- 必须回答用户点击的问题本身，而不是泛泛重复地图解读。
- 必须给出可观察、可执行、可验证的现实建议。

### 4. BodyGraph 与解读本排版拆分

V0.4 不再把长篇“人类图解读本”塞进固定 BodyGraph SVG 下方。

新布局：

- BodyGraph SVG：只保留图形、中心、通道、闸门、左右行星列表、盘面摘要。
- 解读本 HTML：作为图表下方独立阅读区，用响应式卡片排版。
- 导出版本：若导出 PNG/PDF，BodyGraph 和解读本分成不同页面或不同区块。
- 移动端：BodyGraph 可横向适配或缩放，解读本必须单列、字号清晰、段落留白足够。
- 桌面端：图表与解读本可双栏或上下分区，但正文不能挤压到不可读。

解读本排版要求：

- 正文字号不低于 15px，移动端不低于 16px。
- 行高不低于 1.65。
- 每段不超过 120 个中文字符。
- 章节之间必须有明显间距。
- 重点结论使用短卡片或加粗，不堆密集长段。
- 不把大量文字直接写进 SVG 固定坐标里。

## Information Architecture

V0.4 页面结构调整为：

1. 出生资料输入
2. 核心专业配置
3. BodyGraph 图表核验
4. 六张解读地图
5. 地图条目展开区
6. 点击追问深聊区
7. 独立人类图解读本

出生资料输入字段：

- 昵称：可选。
- 性别：男 / 女。
- 出生日期：必填。
- 出生时间：必填。
- 城市：必填。
- 省份/地区：建议填写。
- 国家和时区：不在用户表单中展示；中文版本默认中国标准时间，国际化版本后续单独设计。

地图仍保留 V0.3 的六类：

- 身体地图：身体怎么回应、能量哪里卡住、身体信号如何识别。
- 天赋地图：爻位、通道、关键闸门、天赋成熟表达。
- 财富地图：财富来源、赚钱方式、资源边界、合作与定价。
- 关系地图：适合什么样的人、亲密关系卡点、沟通边界。
- 使命地图：人生主轴、轮回交叉、人格/设计太阳地球组合。
- 专业信息：中心、通道、闸门、行星激活核验。

## Prompt And Knowledge Requirements

V0.4 的 Prompt 不再只传当前地图条目，而是按以下顺序组装：

1. 当前用户完整 chart facts。
2. 当前地图条目事实。
3. 与问题相关的其他盘面特质。
4. 资料库知识原子和解释规则。
5. 用户点击的问题。
6. 回答格式要求。

Prompt 必须明确禁止：

- 只解释单个术语，不结合全盘。
- 编造未定义中心、通道、闸门。
- 把推荐追问回答成和卡片一样的文本。
- 输出“作为 AI”“当前聚焦”“PromptPack”等内部语言。
- 把开放中心说成缺陷，把人类图说成绝对命运。

## Frontend Requirements

### 地图条目

- 条目默认折叠，展开后显示长解读。
- 长解读中必须分段：结论、全盘综合、活出来的人、盲区、卡住状态、为什么会卡住、身体信号、练习、追问。
- `trace` 条目不展示完整诊断区，避免专业信息地图臃肿。
- “可点击追问”按钮固定在条目底部。
- 点击追问后按钮进入 loading 状态，完成后跳转/滚动到聊天回答。

### 聊天区

- 必须显示当前问题来自哪个地图条目，例如“来自财富地图：02-14 通道”。
- 回答区要显示“本次使用的盘面依据”，但用用户语言呈现，不显示内部字段名。
- 如果 DeepSeek 不可用，本地 fallback 也要输出基于全盘综合的结构化回答。

### BodyGraph / 解读本

- BodyGraph 区域只展示图形和核验信息。
- 解读本改为独立 HTML 卡片区。
- 移动端禁止出现小字密集挤压。
- 桌面端正文宽度控制在舒适阅读范围，不超过 760px。

## Implementation Plan

### Phase 1: 综合上下文模型

- 新增 `SynthesisContext` 类型。
- 从 `HumanDesignChart` 提取完整盘面事实。
- 为每个地图条目注入相关全盘特质。
- 增加“相关特质选择器”，按地图类型选择应叠加的中心、通道、闸门、爻位和权威。

### Phase 2: 输入与隐私热修复

- 删除前端“使用示例”按钮。
- 移除所有真实用户硬编码样本。
- 增加性别字段。
- 隐藏国家和时区字段。
- 搜索并清理公开文档、前端、测试 fixture 中可能暴露真实用户资料的位置。
- 增加隐私回归测试，防止后续又把真实资料写进 demo。

### Phase 3: 地图生成器升级

- 扩展 `InterpretationMapItem`。
- 新增 `diagnosis_depth`、`full_chart_synthesis`、`embodied_expression`、`blind_spots`、`stuck_patterns`、`stuck_causes`、`body_signals`、`real_world_applications`。
- 核心 `deep` 条目固定包括：`body.sacral-response-training`、`body.open-pressure-chain`、`wealth.02-14-main-track`、`wealth.promise-boundary`、`talent.profile-24`、`talent.consciousness-cross`、`relationship.emotional-boundary`、`relationship.network-fit`、`mission.generator-cross`。
- 重点升级天赋地图、财富地图、关系地图。
- 匿名回归样本 A 必须在 `2/4 + 纯生产者 + 荐骨权威 + 02-14 + 63/64 | 5/35 + 开放意志力中心` 的组合上形成具体解读。

### Phase 4: 点击追问链路

- 前端把每个追问渲染成按钮。
- 点击按钮调用 `/api/chat`。
- 请求携带地图条目和综合上下文。
- 聊天回答不得复用当前卡片文本。
- 支持 DeepSeek 和本地 fallback 两条路径。

### Phase 5: 解读本排版重构

- 从 BodyGraph SVG 中移除或弱化大段解读本正文。
- 新增独立 `ReadingBook` 组件。
- 调整移动端字号、行高、段落宽度。
- 保留导出能力，但图表和正文分区输出。

### Phase 6: 测试与评审

- 补充综合解读单元测试。
- 补充点击追问 API 测试。
- 补充 UI 交互测试。
- 补充移动端截图/视觉检查。
- 做一轮人工 review，重点看是否仍然泛、是否像术语解释、是否排版清晰。

## Test Plan

### 单元测试

- 前端源码不得包含“使用示例”真实资料预填逻辑。
- API `BirthProfile` 能保存 `gender`。
- 中文用户表单不出现国家和时区输入框。
- `SynthesisContext` 能正确提取类型、策略、权威、人生角色、定义、中心、通道、闸门。
- 每个地图条目必须包含至少 2 个非本条目的相关盘面特质。
- 每个 deep 条目必须包含非空 `embodied_expression`、`blind_spots`、`stuck_patterns`、`stuck_causes`。
- standard 条目至少包含 `blind_spots` 和 `stuck_patterns`。
- trace 条目不得生成长篇诊断，只保留事实核验和防误读。
- 天赋地图不能只解释 `2/4`，必须结合类型、权威、通道和关键闸门。
- 财富地图不能只解释 `14号闸门`，必须结合荐骨、G中心、意志力中心和 02-14。

### API 测试

- `/api/interpretation-maps` 返回 `synthesis_context` 和综合字段。
- `/api/chat` 接收 `entry_source=followup_button` 后返回新生成回答。
- `is_reused_card_text` 必须为 `false`。
- DeepSeek 不可用时 fallback 仍然能输出全盘综合回答。

### 内容测试

- 公开 demo、截图、文档和默认样例不得暴露真实用户姓名、生日、出生时间、出生地。
- 禁止输出泛化句：“你要相信自己”“多觉察”“顺其自然”作为主要结论。
- 禁止只做术语解释。
- 禁止出现非目标术语：骶骨中心、额骨中心、阿扎那。
- 每个深度条目必须说明“活出来的人是什么样子”。
- 每个 deep 条目的 `stuck_causes` 必须同时包含盘面机制和现实场景。
- 每个追问回答必须结合至少 3 个当前盘面事实。

### 视觉测试

- 移动端 390px 宽度下，解读本文字不重叠、不截断、不小于 16px。
- 桌面端 BodyGraph 和解读本分区清晰。
- SVG 中不再承载大量小字正文。
- 点击追问后聊天区自动出现新回答。

### 产品验收

以匿名回归样本 A 做完整验收：

- 天赋地图能解释 `2/4` 在 `纯生产者 + 荐骨权威 + 02-14 + 一分人/二分人` 下如何活出来。
- 财富地图能解释财富来源、赚钱方式、定价边界和开放意志力中心的保财风险。
- 使命地图能把 `63/64 | 5/35` 与 2/4、荐骨权威和 02-14 组合成具体人生主轴。
- 点击“我的财富主航道是什么？”后，聊天回答必须重新生成，并结合全盘，不复制财富卡片。
- BodyGraph 下方解读本在手机端清晰可读。

## Acceptance Criteria

V0.4 完成标准：

- 综合解读完整度：每个地图重点条目都能从单点解释升级为全盘叠加解释。
- 用户语言：普通用户能看懂“我是什么样的人、怎么工作、怎么赚钱、怎么处理关系”。
- 交互完整度：推荐追问可点击、可发送、可得到深度回答。
- 排版可读性：解读本不再挤在图里，移动端阅读体验通过视觉检查。
- Grounding：所有深度回答都基于当前用户真实盘面，不编造事实。
- 内部评分达到 `>= 90/100` 后才进入提交收口。

## Non-Goals

- V0.4 不做付费系统。
- V0.4 不做账号云端历史。
- V0.4 不做双人合盘新产品线。
- V0.4 不宣称科学预测准确率。
- V0.4 不把 MiniMax 图片模型用于正式 BodyGraph 排盘。

## Risks And Mitigations

- 风险：综合解读变长后页面更难读。缓解：强制分段、卡片化、重点高亮和可折叠。
- 风险：大模型追问复述卡片内容。缓解：加入 `is_reused_card_text` 检查和 prompt 约束。
- 风险：综合叠加时误引不存在的盘面事实。缓解：所有 prompt 只允许使用 `chart facts` 白名单。
- 风险：图表排版改动影响导出。缓解：BodyGraph 和 ReadingBook 分离后分别测试导出。
