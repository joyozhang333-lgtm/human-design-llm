# Human Design V0.3 Product Requirements

更新时间：2026-06-05

## 产品定位

V0.3 是面向简体中文用户的人类图解读地图产品。它不是术语查询页，也不是只输出一篇 Markdown 报告，而是把正式排盘结果拆成用户能点击展开的地图：身体、财富、天赋、关系、使命和专业信息。

人类图在本产品中被定位为自我观察、身体资源、能量管理、关系理解和事业方向工具，不作为医疗、心理诊断、法律、财务或确定性命运预测工具。

## 用户体验

- 首页先展示专业配置：类型、策略、权威、人生角色、定义、签名、非自己主题、轮回交叉、已定义中心、开放中心、通道和闸门。
- BodyGraph 保留为图表核验入口，但不压过解读本身。
- 解读入口分为六张地图：身体地图、财富地图、天赋地图、关系地图、使命地图、专业信息。
- 每个地图条目必须能展开，并包含专业依据、用户语言解释、现实生活场景、常见卡点、可执行练习和推荐追问。
- 页面不得向用户暴露内部工程语言，例如“当前聚焦”“问题切口”“焦点提示”“PromptPack”“retrieved knowledge”等。

## 资料库系统

V0.3 的资料库不是一次性文案，而是产品可调用结构：

- `SourceCard`：记录来源、作者、语言、类型、URL、优先级、版权使用方式和产品用途。
- `KnowledgeAtom`：把书籍、官方资料和中文术语转成可复用知识点。
- `InterpretationRule`：把知识点转成可用于具体图表的解释规则。
- `PromptPack`：按地图类型选择资料、规则和系统提示词。

资料库路径：`references/research-corpus/v0.3/`。

版权原则：不复制大段版权原文，只记录来源元信息、摘要、解释原则和原创中文转译。

## API

- `POST /api/charts`：根据出生信息生成正式 chart、BodyGraph 和专业摘要。
- `POST /api/interpretation-maps`：根据 `chart_id`、`map_type` 和 `depth` 返回结构化解读地图。
- `POST /api/chat`：支持 `map_type` 和 `map_item_key`，问答必须基于 chart facts、地图条目和资料库上下文。
- `POST /api/reports`：保留旧版 Markdown 报告能力，但 V0.3 前端默认以地图为主。

## 验收标准

- 张朝阳样本必须能生成六张地图，并在财富地图命中 `02-14`、`14号闸门`、开放意志中心和承诺边界。
- 天赋地图必须体现 `2/4`、`02-14`、`63/64`、`5/35` 和关键闸门组合。
- 聊天 fallback 和 DeepSeek 都必须优先使用当前地图上下文，不能只输出泛泛建议。
- 单盘报告和地图不得出现“骶骨中心、额骨中心、阿扎那”等非目标术语。
- 内部评分必须达到 `>= 90/100`；当前历史 scorecard 输出为 `100/100`。

## 当前限制

- V0.3 资料库是可扩展骨架，已录入核心来源和产品规则，但没有宣称已经完整阅读 200 本版权书全文。
- 当前资料库先采用 JSON/Markdown，本版本不接入向量库；当来源扩展到 200+ 后再评估 embedding 检索。
- 账号、支付、云端历史和正式 PDF 模板不是 V0.3 范围。
